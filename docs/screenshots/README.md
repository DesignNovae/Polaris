## Reproduce the current captures

1. Configure the web application and run `npm run dev`.
2. Follow [the signing setup](../SIGN_LANGUAGE_PRODUCTION.md), then run `npm run signing:worker` for the ASL capture.
3. Sign in with a test account and open Action Lab → Video Learning.
4. Select SAT → Math → Solving linear equations. Enable ASL, wait for generation, play the source, and pause with the figure visible. Keep the source attribution and research-status label visible.
5. Close the player and capture the library filters/cards. Open the IELTS learning paths lower in the library for the path capture.
6. Open Action Lab → Exam Lab and capture the loaded catalog.
7. Inspect every image before committing: check legibility, loading/error states, personal information, and agreement with its README caption.

These authenticated captures are manual and are not generated by `npm run screenshots`.

## Generated captures

Everything else in this directory is produced by:

```bash
npm run screenshots -- --scale 2
```

`--scale 2` is what makes them retina-sharp; without it they are captured at 1× and look soft on a modern display. The script drives headless Chrome over the DevTools Protocol, waits real time rather than virtual time (the landing page animates with GSAP and Lenis, and virtual time fast-forwards past the scroll reveals), hides the Next.js dev overlay, and **closes the docked Strategist panel** before every workspace capture — that panel overlaps the workspace header at 1440px and squeezes the content column, which changes the layout being documented.

Every generated target is a public `/demo` route, so captures use seeded data and can never put a real student's name, email, or plan into a committed image. See [the script](../../scripts/screenshots.mjs) for the target list.
